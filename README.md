# Subsio

> Все подписки и регулярные платежи в одном месте — без доступа к банковскому счёту и с напоминаниями прямо в Telegram.

## О проекте

Subsio — Telegram-first сервис для ручного учёта подписок и других регулярных платежей.

Пользователь сможет видеть будущие списания, понимать общую сумму расходов, хранить информацию о способах оплаты и заранее получать уведомления. После запуска веб-версии интерфейс будет адаптирован под Telegram Mini App.

### Какую проблему решаем

Когда подписок становится много, легко потерять контроль:

- забыть дату следующего списания;
- не помнить, с какой карты производится оплата;
- продолжать платить за неиспользуемый сервис;
- пропустить завершение бесплатного периода;
- не замечать общую сумму ежемесячных и ежегодных расходов.

### Позиционирование

> Subsio — приватный Telegram-first трекер подписок, которому не требуется доступ к банковским данным.

## Продуктовые принципы

- **Сначала работающий продукт.** Короткие циклы: собрать → выпустить → получить обратную связь → улучшить.
- **Privacy-first.** Мы не храним полные номера карт, CVV и другие платёжные реквизиты.
- **Mobile-first.** Интерфейс сразу проектируется с учётом будущего Telegram Mini App.
- **Один понятный контракт.** OpenAPI связывает backend, Orval, SWR и Zod.
- **Надёжные уведомления.** Каждая отправка отслеживается и защищается от дублирования.
- **Монолит до появления причины его разделить.** Без преждевременных микросервисов и Kubernetes.

## Поток данных

```text
Mantine UI
    ↓
React Hook Form
    ↓ zodResolver
Generated Zod schema
    ↓
Generated Orval mutation / SWR hook
    ↓ HTTP
NestJS + Fastify
    ↓
Prisma
    ↓
PostgreSQL
```

Prisma и Orval решают разные задачи:

- **Prisma** соединяет backend с PostgreSQL;
- **Orval** соединяет frontend с backend API;
- **SWR** выполняет запросы и управляет серверным состоянием во время работы приложения.

## Структура репозитория

```text
subscription-manager/
├── apps/
│   ├── web/                 # React-приложение: app → pages → локальные ui/hooks/api
│   ├── bot/                 # grammY-бот: команды, Mini App button и уведомления
│   └── server/
│       ├── src/             # NestJS-модули по бизнес-областям
│       ├── scripts/         # генерация OpenAPI и служебные сценарии
│       └── prisma/          # схема, миграции и seed
├── packages/
│   ├── api-client/          # Orval: SWR-клиент, модели и Zod-схемы
│   ├── domain/              # общая доменная логика без привязки к фреймворку
│   └── ui/                  # общие компоненты поверх Mantine
├── docker/                   # dev/prod Dockerfile и Caddyfile
├── compose.yaml              # локальная разработка
├── compose.production.yaml   # production на VPS
├── .env.example              # только локальные переменные
├── docs/production/README.md # короткая инструкция по production-сборке
├── pnpm-workspace.yaml       # состав monorepo
└── README.md
```

Frontend разбит по тем же практичным принципам, что и рабочий Oxygen admin: страницы и их
`ui`/`hooks`/`api` лежат рядом, общие вещи выносятся только после появления реального повторного
использования. API, worker и Telegram-бот будут запускаться отдельными процессами, но использовать
одну server-кодовую базу и общие доменные модули.

## Основные сущности

### User

Профиль пользователя, timezone, locale, email, Telegram ID и настройки уведомлений.

### RecurringPayment

Подписка или другой регулярный платёж: название, сумма, валюта, категория, периодичность, следующая дата списания и статус.

### PaymentMethod

Безопасное описание способа оплаты: пользовательское название, тип, цвет и последние четыре цифры. Полные реквизиты карты не сохраняются.

### ReminderRule

Правила напоминаний: канал, время и количество дней до списания. У одного платежа может быть несколько правил.

### PaymentOccurrence

Конкретное ожидаемое или подтверждённое списание. Используется для истории и аналитики.

### NotificationDelivery

История уведомлений, попытки доставки, ошибки и idempotency key для защиты от дублей.

## Первая цель

Первый рабочий релиз разработки должен замкнуть полный путь:

```text
Создать подписку
→ проверить данные через Zod
→ отправить Orval mutation
→ обработать запрос в NestJS
→ сохранить через Prisma
→ прочитать из PostgreSQL
→ показать через SWR в React
```

## Локальный запуск

Создайте локальный env-файл и запустите весь стек:

```bash
cp .env.example .env
pnpm install
docker compose up --build
```

### Локальные адреса

| Сервис              | Адрес                                                                    | Как запускается             |
| ------------------- | ------------------------------------------------------------------------ | --------------------------- |
| Web-приложение      | <http://localhost:5173>                                                  | `docker compose up --build` |
| Backend API         | <http://localhost:3002/api>                                              | `docker compose up --build` |
| Swagger UI          | <http://localhost:3002/api/docs>                                         | `docker compose up --build` |
| OpenAPI JSON        | <http://localhost:3002/api/docs-json>                                    | `docker compose up --build` |
| Health check        | <http://localhost:3002/api/health>                                       | `docker compose up --build` |
| Prisma Studio       | <http://localhost:5555>                                                  | `pnpm db:studio`            |
| Mailpit             | <http://localhost:8025>                                                  | `docker compose up --build` |
| PostgreSQL          | `postgresql://subscription_manager@localhost:54329/subscription_manager` | `docker compose up --build` |
| SMTP для разработки | `localhost:1025`                                                         | `docker compose up --build` |

Prisma Studio не входит в основной Compose-процесс: запустите её отдельной командой
`pnpm db:studio`, когда нужен просмотр или ручное редактирование локальных данных.

Локально `TELEGRAM_AUTH_DEV_BYPASS=true` разрешает вход demo-пользователю без Telegram.
В production этот флаг должен быть `false`, а `TELEGRAM_BOT_TOKEN` — передан только backend- и bot-контейнерам.
Локальный бот не стартует с обычным `docker compose up`: он включён в профиль `bot`, чтобы не конкурировать с production-ботом за один Telegram-токен. Запускайте `docker compose --profile bot up bot` только с отдельным dev-токеном или после остановки production-бота.
Worker тоже запускается отдельно: локально `docker compose --profile notifications up worker` только с dev-токеном. Без токена он завершится с ошибкой; обычный `docker compose up` не рассылает сообщения.
После публикации HTTPS-адрес Mini App задаётся через `TELEGRAM_MINI_APP_URL`; бот автоматически
добавляет кнопку запуска, команды и описание профиля, а также проверяет, что токен принадлежит `@SubsioAppBot`.
Пользователь должен отправить боту `/start`: это разрешает личные сообщения и активирует напоминания. Через `/settings` можно поставить их на паузу, включить снова и выбрать время отправки с точностью до минуты в 24-часовом формате. По умолчанию напоминание приходит за день до даты списания в 10:00 по часовому поясу пользователя (сейчас по умолчанию `Europe/Moscow`).

Для запуска приложений на хосте при работающем PostgreSQL:

```bash
pnpm dev
```

Полезные команды:

```bash
pnpm generate     # OpenAPI → SWR client + Zod schemas
pnpm db:migrate   # создать и применить Prisma-миграцию
pnpm db:seed      # добавить демонстрационные данные
pnpm db:studio    # открыть Prisma Studio
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
```
